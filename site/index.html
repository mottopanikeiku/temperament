A shared key component cancels in softmax

Four keys share the same first coordinate. That adds one constant to every attention score, so softmax cancels it and the exact weights stay put as you move the slider. Rotation spreads the shared part across channels, where FP8 rounding erases the small differences between keys.

Vectors and arithmetic

One query, four keys, eight channels. Q and K each use one maximum-based FP8 scale. I apply the same fixed random-sign Hadamard transform to both before rounding. E4M3FN uses round-to-nearest-even and saturation at ±448. Dot products and softmax use JavaScript numbers; Q/K scaling and conversion use float32.

The toy rounds Q/K only and displays attention weights. Centering subtracts the mean key before rotation, preserving exact attention.

Score definitions

For each text, take log(1 + relative Frobenius output error), average over texts, and subtract the unrotated average from the rotated one. The predictor does the same with its estimated errors. The inspector converts back with exp(mean) − 1.

The predictor needs reference attention outputs, so it is an offline diagnostic. OLMo has no harmed heads, so its own AUC is undefined.

Center keys before quantizing

FlashAttention-3 rotates Q and K with a Hadamard transform to spread outliers before FP8 rounding. SageAttention's smooth-K subtracts the mean key first. Both are existing techniques; this page measures them with the real FA3 FP8 kernel.

In the CPU study, centering took Qwen2.5-0.5B's rotated batch exp(CE) ratio from 1.91× to 1.06×. The H100 study repeats the test on eight checkpoints up to 14B.

Protocol, statistics and commands are in the methods page.
